# Semptify — Information Package Index (What to Hand Brad or Opus)

Give Brad or Opus these, in this order, before reasoning about parameters or dispatching any task:

1. **Vision & Build Parameters Brief** (`vision-brief-for-opus.md`) — the why, the one-building architecture, the closing ask.
2. **Opus COO Charter** (`opus-coo-charter.md`) — chain of command, cost/resource rules, how to break down and route work.
3. **Documentation Staleness Protocol** (`documentation-staleness-protocol.md`) — so the recipient knows to distrust unreconciled docs and never blend old/new content itself.
4. **GUI Standing Rules** — layout, one-task-per-page, crisis-help-always-reachable, no dashboards, no card-style containers.
5. **Public Language Rules** — no "evidence"/"win"/"fight" framing, no "log in"/"account" language for storage, never "free" to describe Semptify, source everything.

> Note: items 4 and 5 are standing rules already captured elsewhere in the repo (`docs/admin/MOTIVATIONS.md`, `.devin/rules/`, `AGENTS.md`). Add them to this index only when they are promoted to standalone canonical documents.

## Before Every New Work Session
Ask: has anything in 1–5 changed since the recipient last saw it?
- If **no** — don't resend everything. Re-sending unchanged docs is how old and new copies start blending in the first place.
- If **yes** — hand over only the diff (what changed and why), not the whole document again.

This index itself should get the same treatment: if a new canonical document gets added to the package, add it here and note the date — don't let this list itself go stale.
