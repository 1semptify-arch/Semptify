# Context Explanation Workbook

This workbook is for **content authors, legal reviewers, and tenant advocates** who will write the curated explanation entries that power Semptify's Information Orchestrator / Familiarity Tapering layer.

**No model training is required.** The embedding model (`all-MiniLM-L6-v2`) is a pre-trained, off-the-shelf sentence encoder. Your job is to write the human-readable text that the model turns into a vector. The engineering layer (retrieval, scoring, variant selection) is already built and tested; what is empty is the shelf.

---

## 1. What each entry is

A `ContextExplanationEntry` is a **subject + jurisdiction + pillar + review_status** row with **four variant text slots**. When the system needs to explain something to a tenant, it:

1. Looks up entries matching the tenant's `jurisdiction` and the object's `pillar`.
2. Ranks them by semantic similarity to the tenant's current situation (the query is built from `subject_tags` + `why`).
3. Returns the best match and selects one of the four variants based on the user's `exposure_count` for that function.

Each variant is plain text. **No HTML, no markdown, no links.** The consumer (UI Composer, Page Composer, or a future voice channel) will format and wrap the text.

---

## 2. Schema

| Field | Required | Allowed values | What it means |
|---|---|---|---|
| `entry_id` | auto | `exp_...` | Generated by the system. Do not fill in the workbook. |
| `subject` | yes | one of the 14 canonical subjects (see §5) | The housing-rights topic this entry is about. |
| `jurisdiction` | yes | e.g. `MN` | The state this applies to. Most entries start as `MN`. |
| `upl_risk_tier` | yes | `LOW`, `MEDIUM`, `HIGH` | Legal risk level. `HIGH` should be reviewed by an advocate before being marked `VETTED`. |
| `pillar` | yes | `RECORD`, `KNOW`, `ACT`, `GOVERN` | Which GUI pillar this explanation belongs to. |
| `review_status` | yes | `BETA`, `VETTED` | Start as `BETA`; legal review moves to `VETTED`. Vetted entries are preferred in retrieval. |
| `variant_mechanics` | yes | plain text | **1st exposure** — full, plain-language explanation of what actually happens. |
| `variant_trust` | yes | plain text | **2nd exposure** — why it matters, why the tenant should believe it, what's at stake. |
| `variant_reinforcement` | yes | plain text | **3rd exposure** — short reminder from a different angle. |
| `variant_minimal` | yes | plain text | **4th+ exposure** — status-only or one-line cue. |

---

## 3. The four variant slots and when they appear

This is the exposure-to-variant mapping from `app/modules/context_engine/retrieval.py::select_tapered_variant`.

| Exposure count | Variant returned | Purpose | Voice |
|---|---|---|---|
| 1 | `variant_mechanics` | Tenant has never (or rarely) seen this. Explain the mechanism in full. | Patient, plain-language, step-by-step. |
| 2 | `variant_trust` | Tenant has seen it once. Now explain *why* it matters and *why* they can trust the guidance. | Reassuring, stakes-focused, builds confidence. |
| 3 | `variant_reinforcement` | Tenant is becoming familiar. Reinforce with a shorter reminder or a different angle. | Friendly, brief, assumes they know the basics. |
| 4+ | `variant_minimal` | Tenant knows this. Give a minimal status cue or one-line label only. | Dense, quiet, power-user. Tap/expand to see more if needed. |

**Important:** the slot *names* (`trust`, `mechanics`, `reinforcement`, `minimal`) do not map 1-to-1 to exposure 1-4. The mapping above is canonical. Content authors must write each slot for its actual exposure, not for the name.

## 4. Writing rules

### Audience
- Reading level: **5th grade**.
- Stress level: **high** — the tenant is likely in crisis, on a phone, with no human help.
- Context: they do not care how Semptify works. They care what to do and why.

### Tone
- Active voice, short sentences.
- No jargon. If a legal term is required, define it in the same sentence.
- No marketing language. No exclamation points.
- Be honest about uncertainty: "Semptify cannot tell you the exact deadline without your court date" is better than a confident guess.

### Length targets

| Variant | Target length | Max length |
|---|---|---|
| `variant_mechanics` | 40-80 words | 150 words |
| `variant_trust` | 25-50 words | 100 words |
| `variant_reinforcement` | 15-35 words | 80 words |
| `variant_minimal` | 3-10 words | 25 words |

### Plain-text only
- No HTML tags.
- No markdown (`**bold**`, `[links](...)`, etc.).
- No URLs. If a source is needed, the consumer layer handles that.
- Use single newlines only if they help readability; the consumer may collapse them.

### Embedding signal
The all-MiniLM-L6-v2 model creates one embedding from the concatenated string:

```
{subject} {variant_mechanics} {variant_trust} {variant_reinforcement} {variant_minimal}
```

So the **subject keyword and the most important concepts should appear naturally in the variants**. Do not keyword-stuff; the model understands synonyms and related phrases.

### One entry per subject × jurisdiction × pillar
You can have multiple entries for the same `subject`/`jurisdiction`/`pillar` if they cover genuinely different angles or situations, but each should stand on its own. Retrieval will pick the most semantically relevant one.

## 6. Workbook template (fill this in)

Copy this block and add one row per entry. Each row is one subject/jurisdiction/pillar combination.

```
subject|jurisdiction|upl_risk_tier|pillar|review_status|variant_mechanics|variant_trust|variant_reinforcement|variant_minimal
```

### Example row

```
repair|MN|LOW|RECORD|BETA|When you report a repair problem, Semptify creates a dated record of what you reported, when you reported it, and who you told. This helps you prove later that the landlord knew about the problem.|A written record protects you. If the landlord later claims they never knew about the leak, your dated entry shows otherwise.|Write it down the same day it happens. A short note with the date is enough.|Repair logged.
```

### Full workbook — all 56 combinations

`data/context_explanation_workbook.csv` contains **56 rows**: 14 subjects × 1 jurisdiction (`MN`) × 4 pillars. Each row has pre-filled `upl_risk_tier` and `review_status=BETA`, and the four variant columns contain placeholders like:

`docs/context_explanation_needs.md` is the human-readable companion: it lists every one of the 56 combinations, sorted with the 10 `HIGH`-priority starter rows first, and gives the **context of use** and the four variant prompts for each.

```
[FILL: mechanics — 1st exposure. What actually happens for {subject} in the {pillar} pillar? 40-80 words, plain text, no HTML.]
```

A content author edits the CSV directly (Excel, Google Sheets, VS Code, etc.), replaces the placeholders with real text, and runs the loader. The loader skips any row that still has a `[FILL` or `TODO` marker, so it is safe to load a partially completed workbook — only finished rows get inserted.

### Starter set — 10 suggested entries

If 56 feels like too much at once, fill these first. The rest can stay as placeholders until you need them.

Suggested priority order:

1. `eviction` / `ACT` — eviction defense actions
2. `eviction` / `GOVERN` — high-stakes legal risk notice
3. `repair` / `RECORD` — logging repair requests
4. `repair` / `ACT` — next steps for repairs
5. `rent` / `KNOW` — rent rights
6. `deposit` / `KNOW` — security deposit rules
7. `timeline` / `RECORD` — building a timeline
8. `evidence` / `RECORD` — collecting evidence
9. `retaliation` / `GOVERN` — what counts as retaliation
10. `discrimination` / `GOVERN` — fair housing rights

Then fill in `KNOW`, `ACT`, and `RECORD` variants for the remaining subjects as the product expands.

## 7. Loading the workbook

### Option A: CLI loader

Run the loader from the Semptify repo root:

```powershell
.\venv311\Scripts\python.exe tools\load_explanation_workbook.py data\context_explanation_workbook.csv
```

The loader validates each row, generates embeddings, and inserts/updates the `context_explanation_entries` table. It skips bad rows and reports them at the end.

### Option B: admin API

POST to `/api/context/explanations` with admin credentials:

```json
{
  "subject": "repair",
  "jurisdiction": "MN",
  "upl_risk_tier": "LOW",
  "pillar": "RECORD",
  "review_status": "BETA",
  "variant_mechanics": "...",
  "variant_trust": "...",
  "variant_reinforcement": "...",
  "variant_minimal": "..."
}
```

### Option C: admin web form

If a browser UI is needed later, the existing API can be wrapped in a small `/admin/explanations` form. That is not built yet; ask for it if the CLI becomes painful.

## 8. Re-checking the 0.45 threshold

The current `LAYER2_CONFIDENCE_THRESHOLD` is `0.45`. It was calibrated against a small synthetic test set. Once you have 20-30 real entries, run:

```powershell
.\venv311\Scripts\python.exe -m pytest tests\test_context_engine_retrieval.py -v
```

If real queries return mostly below 0.45 or mostly above 0.75, the threshold may need a five-minute tuning pass. Do not change the threshold before there is real content to calibrate against.
