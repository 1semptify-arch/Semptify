Admin Portal Overview

The Semptify Admin Portal provides system-wide oversight, configuration, and maintenance tools. Access requires admin credentials and 2FA authentication.

◆ Access Requirements

Authentication: Username + Password + 6-digit TOTP code

Environment Variables Required:

  • ADMIN_USERNAME - Admin username (default: "admin")
  • ADMIN_PASSWORD - Admin password
  • ADMIN_TOTP_SECRET - TOTP secret for 2FA

Admin Dashboard

Location: /admin/dashboard.html

Purpose: Central hub for system monitoring, user management, and quick access to admin tools.

1. System Overview Hero▸

What it does: Displays high-level platform metrics at a glance.

Metrics shown: Total users, Active cases, Documents in vaults, Pending signatures, Uptime, Security incidents, Rate limit violations, Blockchain timestamps.

○ How to Use

Monitor these metrics daily to detect anomalies. Sudden drops in uptime or spikes in rate limit violations may indicate attacks or system issues.

○ Testing

No switches to test. Metrics are read-only from database.

▸ Troubleshooting
  • Metrics not loading: Check database connection. Verify get_db_session() is working.
  • Stale data: Metrics may cache for up to 5 minutes. Refresh page.
2. User Search Widget▸

What it does: Search for users by ID, email, or name. View user details and perform admin actions.

Admin Actions: Impersonate (log in as user), Reset Gates (reset onboarding gates), View Vault (view vault summary).

○ How to Use
  1. Enter search term in input field
  2. Click "Search" button
  3. Click on a user result to view details
  4. Use action buttons: Impersonate, Reset Gates, View Vault
▸ Troubleshooting
  • Search returns 403: Verify admin role is set in cookie. Check _guard_role_page() middleware.
  • Impersonate fails: Check if impersonation endpoint exists at /admin-console/api/users/{user_id}/impersonate.

Function Browser

Location: /admin/function-browser.html

Purpose: Interactive documentation of all Semptify functions. View function details, inputs, settings, and related pages.

1. Filter by View▸

What it does: Filter functions by page group (Home, Library, Office, Tools, Help).

○ How to Use

Click filter buttons to show only functions in that group. Click "All" to show all functions.

▸ Troubleshooting
  • Filter not working: Check JavaScript filter logic in function-browser.html.

Contract Browser

Location: /admin/contract-browser.html

Purpose: View and verify page contracts and module contracts. Check health status and violations.

1. Health Bar▸

What it does: Shows overall contract health status (pass/fail) and summary statistics.

○ How to Use

Monitor overall system health. Green = all contracts healthy. Red = violations detected.

▸ Troubleshooting
  • Health not loading: Check if health endpoint exists at /api/workflow/health.
  • Always failing: Review contract violations. Fix underlying issues.

Page Editor

Location: /admin/page-editor.html

Purpose: Edit static HTML files and Jinja2 templates directly in the browser with live preview.

1. Save File▸

What it does: Save current file changes to the server.

○ How to Use

Click Save button or press Ctrl+S. Status bar shows "Saved [filename]" on success.

▸ Troubleshooting
  • Save failing: Check if save endpoint exists at /api/editor/save.
  • Permission error: Check file system permissions for the target file.

Review Checklist

Location: /admin/review-checklist.html

Purpose: Run automated verification tests for contracts, routes, SSOT compliance, footer consistency, and security.

1. Run Tests Button▸

What it does: Run all automated tests in sequence and display results.

○ How to Use

Click "Run Tests" button. Wait for all tests to complete. Review results panel.

▸ Troubleshooting
  • Tests not running: Check JavaScript test execution logic.
  • Tests hanging: Check if any test has infinite loop or timeout.

Fix-It Bot

Purpose: Automated issue detection and resolution system that fixes problems without deleting data or functionality.

▸ Design Principles

  1. Never Delete: The bot never deletes data, files, or configurations. It only fixes, adds, or modifies.
  2. Root Cause First: Always identify and fix the root cause, not symptoms.
  3. Safe Rollback: All changes are logged and can be rolled back if needed.
  4. Human Review: Critical fixes require human approval before execution.
  5. Explainable: Every fix includes a clear explanation of what was changed and why.
1. Automated Health Checks▸

What it does: Continuously monitors system health and detects issues.

Checks performed: Database connection, Storage provider connectivity, API endpoint availability, SSL certificate validity, Disk space, Memory usage, Error rate monitoring.

▸ Troubleshooting
  • Bot not detecting issues: Check health check logic. Verify monitoring endpoints.
  • Alerts not sending: Check notification configuration.

Troubleshooting Guide

Issue: Admin Login Fails with 401 Unauthorized▸

Symptoms: Admin login returns 401 error, TOTP code always rejected, "Invalid credentials" message.

Root Causes: ADMIN_PASSWORD not set, ADMIN_TOTP_SECRET not set, Clock drift, Wrong TOTP code.

Fix: Set missing environment variables in .env or Render dashboard, Sync server time with NTP, Regenerate TOTP secret if needed.

Issue: Dashboard Metrics Not Loading▸

Symptoms: Dashboard shows "Loading..." indefinitely, Metrics display as zero, Console shows 500 errors.

Root Causes: Database connection failed, Metrics query timed out, Missing database tables, Insufficient permissions.

Fix: Fix database connection string, Create missing tables via Alembic migrations, Optimize slow queries, Grant necessary permissions.

◆ Severity Levels

  • Critical: System down, data loss, security breach (Within 1 hour)
  • High: Major feature broken, significant impact (Within 4 hours)
  • Medium: Minor feature broken, workaround available (Within 24 hours)
  • Low: Cosmetic issue, minor inconvenience (Within 3 days)
